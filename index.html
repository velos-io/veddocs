Developer environments, inverted.

Ved is a high-performance deployment compiler and orchestrator. It compiles declarative service specifications into deterministic Docker Compose and Kubernetes configurations.

Architecture: Rust Native
Spec: Vedfile (Starlark)
Runtime: .ved/
Wrapper: ./vew

Installation Options

Choose the installation path best suited for your operating system and workflow.

1. Homebrew

Recommended for macOS and Linux developers using the Homebrew package manager.

2. Project Wrapper (`vew`)

Zero system dependencies. Commits directly into projects and pins compiler versions.

3. Pre-built Tarball

Direct download of standalone binaries for CI/CD environments and Docker images.

4. Build from Source

Compile latest development commits directly using the Rust Cargo toolchain.

Option 1: Homebrew (macOS & Linux)

Install via the official tap:

Terminal 
brew tap velos-io/tap
brew install velos-io/tap/ved

Verify the binary is available:

Terminal 
ved --version

Option 2: The `vew` Wrapper (Recommended for Repositories)

Like gradlew or mvnw, Ved provides vew. When you run ./vew in any initialized project, it resolves the pinned version in .ved-version, automatically downloads the correct binary to .ved/bin/, and executes it transparently.

Terminal 
./vew compile
./vew up

Option 3: GitHub Releases (Direct Tarball)

Download the pre-compiled binary matching your CPU architecture:

macOS Apple Silicon (ARM64) 
curl -fsSL https://github.com/velos-io/homebrew-tap/releases/download/v0.1.11/ved-darwin-arm64.tar.gz | tar -xz
sudo mv ved /usr/local/bin/
Linux x86_64 (AMD64) 
curl -fsSL https://github.com/velos-io/homebrew-tap/releases/download/v0.1.11/ved-linux-amd64.tar.gz | tar -xz
sudo mv ved /usr/local/bin/

Option 4: Cargo (From Source)

Terminal 
cargo install --git https://github.com/velos-io/velos --bin ved

Project Setup Options

Ved provides dedicated initialization workflows to onboard existing repositories or start new stacks in seconds.

1. Initialize a Clean Project

Scaffolds the vew wrapper script, pins .ved-version, configures .ved/ workspace, and creates a template Vedfile:

Terminal 
ved init

2. Migrate from Docker Compose

Convert an existing docker-compose.yml file into a native, strongly typed Vedfile:

Terminal 
ved init --compose docker-compose.yml

Ved accurately preserves volumes, host port bindings, multiline health checks, environment parameters, build targets, and container network dependencies.

3. Auto-detect Multi-module Projects

Scans the repository tree for project build files (Maven pom.xml, Gradle build.gradle, Rust Cargo.toml, Go go.mod, Node package.json, Python pyproject.toml) and automatically builds service topologies:

Terminal 
ved init --project

4. Clean Up Workspace

Safely cleans up generated .ved/ artifacts, wrapper scripts, and specification files:

Terminal 
ved deinit
# or force without prompt:
ved deinit --force

Specification Guide: `Vedfile`

Ved specifications are defined in a file named Vedfile using Starlark — a deterministic, hermetic subset of Python developed by Google. This grants configuration files loops, conditionals, and variables without external side effects.

Example `Vedfile`

Vedfile 
"""Production service specification."""
from ved import Service, Port, Mount, Health

backend = Service(
    name="order-api",
    image="ghcr.io/acme/order-api:v2.4.0",
    ports=[Port(8080, host=8080)],
    env={
        "PORT": "8080",
        "DATABASE_URL": "postgres://app:secret@db:5432/orders",
    },
    mounts=[
        Mount.volume("order-data", "/var/lib/orders"),
    ],
    wait_for=["db"],
    health=Health(
        http_get="http://localhost:8080/health",
        interval=5,
        timeout=3,
        retries=5,
    ),
)

database = Service(
    name="db",
    image="postgres:16-alpine",
    ports=[Port(5432, host=5432)],
    env={
        "POSTGRES_USER": "app",
        "POSTGRES_PASSWORD": "secret",
        "POSTGRES_DB": "orders",
    },
)

services = [backend, database]

Shorthand Specification (`ved.yaml`)

Ved also natively parses declarative YAML specifications named ved.yaml or .ved for straightforward setups:

ved.yaml 
version: "1.0"
services:
  database:
    image: postgres:16-alpine
    ports:
      - "5432:5432"
    env:
      POSTGRES_PASSWORD: secret

  web:
    image: nginx:alpine
    ports:
      - "80:8080"
    depends_on:
      - database

Curated Stacks Catalog

Import battle-tested infrastructure bundles directly into your Vedfile:

Vedfile 
from ved import Stack

# Add full OpenTelemetry stack: Jaeger, Prometheus, Collector, Grafana
Stack.add("otel")

The otel stack automatically provisions and connects:

  • Jaeger — Tracing UI on port 16686
  • Prometheus — Metrics engine on port 9090
  • OTel Collector — Telemetry pipeline on ports 4317 (gRPC) & 4318 (HTTP)
  • Grafana — Dashboard UI on port 3000 with anonymous access

CLI Subcommand Reference

Command Description Typical Usage
compile Compile specification into target runtime manifests ved compile
up Compile and bring up stack containers ved up -d
down Stop and preserve stack containers ved down
ps View container statuses, health, and exposed ports ved ps
reset Tear down containers and wipe persistent volumes ved reset --force
test Execute smoke tests against configured health endpoints ved test
validate Validate specification syntax against JSON schema ved validate
build Build workspace modules via detected toolchains ved build
sync Rescan workspace and refresh cached module state ved sync
init Scaffold wrapper and template Vedfile ved init
deinit Remove Ved files and runtime state ved deinit
version Print compiler version information ved version
